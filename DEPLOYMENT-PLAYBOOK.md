# 🚀 Vibe Coding Deployment Playbook (Vercel & GitHub)

This is your master checklist for taking a local Vibe Coded React project from your computer and deploying it live to the internet. Keep this file handy for your next projects (like the Twitter Thread Engine)!

## 🛠️ Phase 1: GitHub Desktop Syncing (The Code Transport)

Vercel pulls code directly from GitHub. So the very first step is safely getting your code onto a GitHub repository.

1. **Add Local Repository**: Drag your project folder into GitHub Desktop, or click *Add Local Repository*. If it says "Create a new repository", go ahead and initialize it.
2. **Defend Against Massive "AI Memory" Files**:
   > [!WARNING]
   > Vibe Coding generates thousands of hidden AI log files (like `.local` or `.agents`). **Never upload these.**
   - Open your hidden `.gitignore` file.
   - Add `.local/` and `.agents/` to block them from Git.
   - **Check GitHub Desktop**: Ensure the changed file count drops from `30,000+` down to exactly the files you coded (e.g., `30` files).
3. **Commit & Push**: 
   - Type a message (e.g., "Initial Engine Commit").
   - Click **Commit to main**.
   - Click the **Push origin** / **Publish** button at the top to send it to the cloud.

---

## 🌩️ Phase 2: Vercel Configuration (The Engine Room)

Once the code is on GitHub, Vercel connects to it and builds it like a virtual computer.

1. **Import the Project**: Log into Vercel, hit **Add New > Project**, and import your GitHub repository.
2. **Handle Monorepos (Workspaces)**:
   > [!IMPORTANT]
   > Because you built an advanced project (a workspace with multiple internal folders like `lib` and `artifacts`), Vercel might get confused.
   - **Root Directory**: Select the very top-level folder (the root `/` or `.`). Do not select a child folder like `api-server`.
   - **Application Preset**: Change it to **Vite** (or leave it as *Other* if Vercel automatically detects the custom `pnpm --filter` build commands).
3. **Routing the Output Directory**:
   - Vercel needs to know *exactly* where the final HTML file generated by Vite lives. 
   - Since Vite compiles to `dist/public`, you must expand **Build & Development Settings**.
   - Override the **Output Directory** to exactly target it: `artifacts/sql-carousel/dist/public`

---

## 🕵️ Phase 3: Troubleshooting Strict Compiler Errors

The cloud is much stricter than your local machine. If Vercel fails to build, it is usually because it caught something your local dev environment ignored.

### 1. Missing Dependency Mappings
- **The Issue**: Vercel threw a `Rollup failed to resolve import "lucide-react"` error. 
- **The Lesson**: Your local server (`pnpm dev`) is lazy and automatically found the icons. Vercel's production compiler (`pnpm build`) requires *strict permission rules*. 
- **The Fix**: We explicitly added `"lucide-react"` into the `dependencies` mapping of the internal engine's `package.json`.

### 2. The Dominant "Source of Truth" (`vercel.json`)
- **The Issue**: You changed the Output Directory to `/public` in the Vercel dashboard, but it still gave a 404 error!
- **The Lesson**: If your project folder has a hidden `vercel.json` configuration file, Vercel will prioritize *whatever is written in that file* over whatever you click on the website. 
- **The Fix**: We went into the code, changed `"outputDirectory"` inside `vercel.json` locally, and pushed it back up to GitHub.

---

## 🟢 Phase 4: Live Verification

1. **Deploying**: Once pushed, Vercel automatically creates a brand new deployment. You can watch it build in the **Deployments** tab.
2. **Defeating the Browser Cache**:
   > [!TIP]
   > If Vercel says it is successful, but your screen still shows an old `404 NOT FOUND` error, your web browser is likely **caching** (saving) the old error to load it faster.
   - Use a **Hard Refresh** (`Ctrl + Shift + R`) to force the browser to pull the new, live visual bundle. 

### Final Result
A pristine, highly functional, beautifully crafted web application sitting on a permanent URL ready for the world to see! 🚀
